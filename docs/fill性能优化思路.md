# fill 阶段性能优化思路（harness 节点提速实践）

> 背景：harness 节点 = claude CLI agent 在工作区内自主完成填表任务。
> 初版实测 **9m15s**，经四轮"测量 -> 定位 -> 优化"迭代降至 **3m11s（-63%）**。
> 本文沉淀思路与通用方法论，适用于任何 agent/harness 型节点。

## 0. 前提：先测量，再优化

分节点 debug 日志（`harness_debug/<工作区>.log`，`--debug-file` 注入）后，统计两个指标：

- **轮次**：`API REQUEST` 行数 = agent 往返次数
- **轮时长**：相邻请求的时间差 = 生成 + 工具执行的耗时分布

瓶颈只有两类，对策完全不同：

| 瓶颈类型 | 日志特征 | 对策方向 |
|---|---|---|
| 轮次太多 | 几十轮、每轮 2~8s 的小轮 | 砍探查、砍往返（优化 1/2/3） |
| 单轮太长 | 少数 100s+ 巨型轮 | 砍生成体积、换快模型（优化 4） |

## 优化一：原语 skill 化（消除逐段探查）

**问题**：agent 自由操作 docx 时，只能用 `P[15]/runs[2]` 这类魔法下标逐段试错（读一段、改一处、看报错、再试），一轮只推进一小步。

**思路**：把实战脚本中的确定性 python-docx 操作提炼为**前缀锚定原语**（`fill_skill.py`），自动投放进工作区：

- `fill_blank(doc, "项目名称：", value)` -- 下划线填空（值填*在线上*，见下）
- `fill_cell / replace_in_para / insert_picture_after / ensure_readable_img`
- 前缀锚定而非下标：模板微调不错位，agent 免探查

**关键细节（下划线填空语义）**：优先填**带下划线格式的空白 run** -> 其次替换下划线字符 run 并留余线 -> 再无则复制邻近格式插入带下划线 run。修复了"值附加在下划线之后"的格式缺陷。

**效果**：轮次 43 -> 34，耗时 -23%。

## 优化二：声明式清单 + 批量报错（一次成型）

**问题**：agent 写脚本、跑、报错、修一行、再跑……错误逐个暴露，往返被拉长。

**思路**：`run_fill_plan(template, output, PLAN)`--把填写/插图全部组织为**声明式操作列表**，一次执行：

```python
PLAN = [
  {"op": "blank", "prefix": "项目名称：", "value": "……"},
  {"op": "cell", "table_header": ["序号", "服务期"], "row": 1, "col": 1, "value": "……"},
  {"op": "picture", "prefix": "备注：", "img": "<绝对路径>", "caption": "附：营业执照"},
]
errors = run_fill_plan('标书模板.docx', 'forms.docx', PLAN)
```

单条失败**不中断**，执行完返回全部错误清单 -> agent 一轮批量修正。

**效果**：轮次 34+29 -> 12+14（探查轮基本归零）。

## 优化三：材料预注入（消除读文件轮次）

**问题**：仍有轮次耗在"读 facts.yaml / metadata / 看模板结构"上。

**思路**：节点代码在调 harness 前，把全部材料直接拼进 prompt（`fill_context.build_fill_context`）：

- **模板可填点地图**：`dump_fill_points(doc)` 一条命令输出全部段落（含填空线标记）+ 表格表头
- facts.yaml / metadata.yaml 全文
- kb 图片**绝对路径**清单

prompt 明令"材料已附，禁止再读文件探查"。

**效果**：轮次再 -52%；但暴露新瓶颈--**巨型生成轮**（185s + 99s 占总时长 57%）：一次要生成几百行 PLAN。

## 优化四：确定值预填（压缩生成体积）

**问题**：PLAN 里大量条目是"已知值"--项目名称/编号/备案号/投标人/法人/信用代码，且在封面/投标函/开标一览表等多处重复出现。

**思路**：`prefill_known(模板副本, state)`--节点代码直接把这些确定值 `fill_all_blanks` 预填进模板副本（值来自 facts.template_fields + 企业资料 + metadata），prompt 标注"系统已预填字段（勿重复填写，发现遗漏才补）"。

**效果**：轮次 9+9，总耗时 **3m11s**。生成体积减半，巨型轮消失。

## 实测数据汇总

| 版本 | 总耗时 | forms 轮 | commercial 轮 | 提速 |
|---|---|---|---|---|
| 自由探查（初版） | 9m15s | 43 | - | 基线 |
| + skill 化 | 7m05s | 34 | 29 | -23% |
| + 声明式清单/材料预注入 | 8m40s | 12 | 14 | 持平（瓶颈转移） |
| **+ 确定值预填（最终）** | **3m11s** | **9** | **9** | **-63%** |

注：fill 三节点在 LangGraph 中 fan-out 并行，总耗时取 max 不叠加；偏离表节点按响应模板判断跳过（0 耗时）。

## 剩余瓶颈与进一步方向

剩余耗时 ≈ **非平凡内容生成**（报价表、资格证明、业绩描述等）= 内容量 × 模型输出速度的物理下限。可继续的方向：

1. **换快模型**：`.env` 配 `HARNESS_MODEL` 指向更快端点，按速度倍数线性收益
2. **更激进架构**：agent 单轮输出 PLAN JSON、节点本地执行 `run_fill_plan` -- 把 CLI agent 降为一次 LLM 调用（失去自主修错能力，需权衡）
3. 9 轮已接近当前模式地板（写 PLAN -> 跑 -> 修 ≈ 3 轮起步 + 模型自检轮）

## 方法论总结（可迁移）

任何 agent/harness 节点的提速四步：

1. **分节点日志 + 轮次统计**：确认是"轮次多"还是"单轮长"
2. **确定性操作下沉为代码**：agent 只做判断，不做机械操作（skill 化）
3. **往返批量化**：声明式清单 + 批量报错，把 N 次试错压成 1 次修正
4. **信息与确定值前置**：材料预注入 prompt、已知值代码直填，只让模型生成"真正需要生成的部分"
